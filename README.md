# 光子仿真图件与文献小工具集

五个**纯标准库 + 一个可选依赖**的小工具，都是做光子器件仿真时为了"让证据可复核"而写的。
只解决很小的问题，但每个都对应一个真实踩过的坑。

| 工具 | 一句话 | 依赖 |
|---|---|---|
| `fig_channel/` | 给图件打**渠道标签**（官方导出 vs 外部绘图），标签写进 PNG 元数据 | matplotlib（生成端） |
| `fig_index/` | **审计**一整个图目录：每张图的渠道、字节、像素、md5，并揪出缺标签的外部图 | 无（纯标准库）+ `fig_channel` |
| `rasterize_pdf/` | 把 PDF 指定页**光栅化成 PNG**（可选先下载），用于"必须从图上读数"的场合 | pymupdf |
| `oa_locate/` | 由 DOI 查**开放获取副本**（OpenAlex API），绕开出版商对脚本请求的拦截 | 无 |
| `probe_download/` | 批量试 URL，把状态码 / 头 / 内容魔数写进日志 | 无 |

## 为什么会有这套工具

做仿真的人都会遇到同一类问题：**报告里的图和数，别人没法核**。具体表现有三种：

1. **图的来源分不清。** 求解器自己导出的场图，和用 matplotlib 重画的曲线，
   证据等级完全不同，但放在一个目录里肉眼分不出来。
2. **数只能从图上读。** 有些参数（渐变段几何、层序）论文里只画在图里、正文没给。
   凭印象抄下来是没法辩护的 —— 必须能**指定页码、指定 dpi 重现同一张光栅图**。
3. **文献取不到就卡住。** 出版商站点对脚本请求返回 418/403，
   于是"没法再看一眼那张图"就变成了一个设计决策的阻塞项。

这五个工具就是针对这三条的：**把"图是谁画的"变成一个可审计的字段**，
**把"从图上读数"变成一条可重放的命令**，**把"取不到文献"变成一次 API 查询**。

## 安装

```powershell
# 只需要 matplotlib（生成端）与 pymupdf（光栅化）
pip install matplotlib pymupdf
# fig_index / oa_locate / probe_download 只用标准库
```

Python 版本：3.8+（全部使用 `from __future__ import annotations`，无第三方运行时依赖）。

## 目录约定

每个工具自带 README（用途 / 依赖 / 最小用法示例）。`fig_index` 依赖 `fig_channel`，
两者需在同一个 `sys.path` 目录下（把两个目录的内容放一起，或设 `PYTHONPATH`）。
